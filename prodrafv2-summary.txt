repo: https://github.com/Kxntxrn/prodrafv2
หมายเหตุ: สรุปจาก backend.zip และ frontend.zip ที่ส่งมา ไม่ได้เห็น
firestore.rules, firebase.json หรือหน้า Firebase Console จริง
ส่วนที่เป็นข้อสันนิษฐานจะมีคำว่า "น่าจะ" กำกับ


---------------------------------------------------------------------
1. ภาพรวมสถานะตอนนี้
---------------------------------------------------------------------
- Frontend: React 19 + TypeScript + Vite คุยกับ Firebase (Auth + Firestore)
  ตรงๆ จากเบราว์เซอร์ ไฟล์หลัก src/lib/db.ts (ฟังก์ชันฐานข้อมูล) และ
  src/App.tsx (ราว 1,000 บรรทัด คอมโพเนนต์เดียว สลับหน้าด้วย state)
- Backend: โค้ด Express + Mongoose เดิมไม่ได้ใช้แล้ว app.js เหลือแค่
  stub บอกว่า "ย้ายไป Firestore แล้ว"
  => การย้าย Mongo -> Firebase ฝั่ง frontend น่าจะเสร็จแล้วหรือเกือบเสร็จ
- ฟังก์ชันที่มีแล้ว: ล็อกอิน Google, ดูรายการของ, ขอยืม, ดูประวัติของตัวเอง,
  หน้าแอดมิน (อนุมัติ/ปฏิเสธ/รับคืน, จัดการของ, ดู audit log)
- ยังไม่มี: QR code, ถ่ายภาพตอนคืน, แชตบอท, เทสต์, README ที่ใช้งานได้,
  เส้นทาง (router) จริง


---------------------------------------------------------------------
2. สิ่งที่ทำไว้ดีแล้ว
---------------------------------------------------------------------
- โครงสร้าง backend เดิมแบ่งชั้นชัดเจน (controllers/routes/validations)
- การอนุมัติและรับคืนใน db.ts ใช้ runTransaction ตัดสต็อกแบบ atomic
- มี audit log บันทึกการกระทำสำคัญ
- ตั้ง TypeScript, ESLint, Prettier ไว้แล้ว
- ไม่มี secret ฝังในโค้ด backend (apiKey ใน frontend/src/config/firebase.ts
  เป็น config ฝั่งเว็บที่เปิดเผยได้ตามปกติ ความปลอดภัยอยู่ที่ Security Rules)


---------------------------------------------------------------------
3. ปัญหาที่ต้องแก้ก่อน (เรียงตามความสำคัญ)
---------------------------------------------------------------------
[วิกฤต] 3.1 สิทธิ์แอดมินปลอมได้
  - db.ts ตั้ง role ฝั่ง client: อีเมลใน ADMIN_EMAILS หรืออีเมลที่มีคำว่า
    "admin" จะได้เป็นแอดมินอัตโนมัติ ใครสมัครอีเมลแบบ admin123@... ก็ได้สิทธิ์
  - และเพราะเขียนเอกสาร users/{uid} จากเบราว์เซอร์ ถ้า rules ปล่อยให้เจ้าของ
    เขียนเอกสารตัวเอง ใครก็แก้ role เป็น admin ได้
  - วิธีแก้: ใช้ Firebase custom claims (ตั้งด้วย Admin SDK ผ่านสคริปต์
    make-admin.js ที่มีอยู่) แล้วให้ Security Rules เช็ค
    request.auth.token.admin == true ห้าม client เขียนฟิลด์ role
  - ลบการตัดสินสิทธิ์จากอีเมล และเอาอีเมลจริงออกจากโค้ดใน repo สาธารณะ

[วิกฤต] 3.2 Security Rules
  - ใน zip ไม่มี firestore.rules / firebase.json ให้เช็คในหน้า Firebase Console
    ว่า rules ปัจจุบันเป็นอะไร ถ้าเป็น test mode ข้อมูลอาจเปิดหรือกำลังจะปิด
  - ต้องเขียน rules ให้ครบ: ผู้ใช้อ่าน/สร้างได้เฉพาะ borrowings ของตัวเอง,
    แก้สถานะได้เฉพาะแอดมิน, items แก้ได้เฉพาะแอดมิน, auditLogs อ่านได้เฉพาะ
    แอดมินและห้าม client เขียนเอง (ให้เขียนผ่านฝั่ง server)
  - เก็บ rules ไว้ใน repo (firestore.rules) และตั้ง firebase.json

[วิกฤต] 3.3 backend/src/config/firebase.js (โค้ดเก่า)
  - ถ้า verifyIdToken ไม่ผ่านจะถอดรหัส JWT โดยไม่ตรวจลายเซ็น และรับ
    token "mock-admin-token" => ปลอมตัวเป็นใครก็ได้
  - ถ้าเคย deploy ไว้ที่ไหน ให้ปิดทันที แล้วลบไฟล์นี้ (โค้ดเก่าทั้งก้อนลบได้)

[สำคัญ] 3.4 ตรรกะยืม-คืน
  - สถานะ borrowed กับ overdue ไม่เคยถูกตั้ง (approved -> returned เลย)
    และสาขา else สุดท้ายใน updateBorrowStatus ยอมให้ตั้งสถานะอะไรก็ได้
    => ควรมีตารางทรานซิชันที่อนุญาตชัดเจน:
       pending -> approved/rejected, approved -> borrowed (สแกน QR รับของ),
       borrowed -> returned (ต้องมีรูป), borrowed -> overdue (งานเช็คเวลา)
  - ใน Firestore transaction ต้องอ่านทั้งหมดก่อนเขียน ลูป get-แล้ว-update
    ทีละรายการในอนุมัติ/คืน จะพังเมื่อรองรับคำขอหลายชิ้นในใบเดียว
    (ตอนนี้ฟอร์มสร้างครั้งละชิ้นเดียวจึงยังไม่เจอ)
  - บันทึก audit log หลัง transaction ไม่ใช่ใน transaction เดียวกัน
    และให้ client เขียนได้ ควรย้ายไปฝั่ง server

[ปานกลาง] 3.5 อื่นๆ
  - backend/.env.example, .gitignore, README.md ว่างเปล่า (ใส่ .env และ
    ไฟล์ service account ใน .gitignore)
  - Dockerfile ของทั้งสองฝั่งรัน npm install และ frontend รัน dev server
    ใช้ได้สำหรับพัฒนา ส่วน production ให้ build แล้ว deploy (Firebase Hosting)
  - ไม่มีเทสต์ ไม่มี CI
  - App.tsx ไฟล์เดียวยาว ~1,000 บรรทัด ควรแยกหน้า/คอมโพเนนต์ และใช้ router

4. ฟีเจอร์ที่วางแผนไว้ ควรเพิ่มตรงไหน
---------------------------------------------------------------------
4.1 เจนโค้ด QR ให้ของแต่ละชิ้น
  - ปัญหา: Item ตอนนี้เก็บแค่จำนวน (totalQuantity/availableQuantity)
    ไม่มีระเบียนของแต่ละชิ้นจริง
  - เพิ่ม subcollection items/{itemId}/units/{unitId}
    (ฟิลด์: serial, status, location, qrId)
  - QR เก็บแค่ unitId สั้นๆ (เช่น nanoid) ไม่ฝังข้อมูลทั้งก้อน
  - ไลบรารี: qrcode (สร้าง), html5-qrcode หรือ @zxing/browser (สแกน)
  - หน้าใหม่: พิมพ์ป้าย QR เป็นชุด (export PDF), หน้าสแกนรับของ/คืนของ
  - เปลี่ยนใบยืมให้ชี้ unitId แทนชื่อสินค้า

4.2 ถ่ายภาพยืนยันตอนคืน
  - ใช้ <input type="file" accept="image/*" capture="environment"> ก่อน
    แล้วบีบอัดรูปก่อนอัปโหลด
  - เก็บรูปใน Firebase Storage เก็บเฉพาะ path + metadata ใน borrowings
  - บังคับให้มีรูปก่อนเปลี่ยนสถานะเป็น returned และเขียน Storage Rules
    ให้ผู้ใช้อัปโหลดได้เฉพาะของตัวเอง
  - (ทางเลือกภายหลัง) ให้ AI เทียบรูปก่อนยืม/ตอนคืน แต่ให้คนยืนยันขั้นสุดท้าย
  - ระบุนโยบายเก็บ/ลบรูป (ข้อมูลส่วนบุคคล PDPA)
  - เช็คเงื่อนไข/ราคาของ Firebase Storage ล่าสุดก่อนเปิดใช้

4.3 แชตบอท
  - ต้องเรียก LLM API จากฝั่ง server เท่านั้น (ซ่อน API key) ใช้โฟลเดอร์
    backend ที่ว่างอยู่ หรือ Cloud Functions
  - ให้บอทใช้ tool calling ดึงข้อมูลจริง (ของว่างไหม ถึงกำหนดคืนเมื่อไหร่)
    ผ่าน Firebase Admin SDK และตรวจ token ของผู้ใช้จริงทุกครั้ง
  - ใส่ rate limit, จำกัดสิ่งที่บอทแก้ข้อมูลได้, เก็บ log
  - ค่า API ต้องจ่ายแยกจากแพ็กเกจสมัครใช้งานแชต ถ้างบน้อยเริ่มจาก
    บอทแบบเรียบง่าย (FAQ + เช็คสถานะ) ใช้โมเดลเล็ก จำกัดความยาวคำตอบ

4.4 ให้ทันยุค (ทำทีหลังได้)
  - แจ้งเตือนผ่าน LINE (LINE Notify ปิดบริการแล้ว ให้ใช้ Messaging API)
  - PWA ให้ติดตั้งบนมือถือ
  - ระบบแจ้งเลยกำหนดคืนอัตโนมัติ (scheduled function)

6. เรื่องค่าใช้จ่าย
---------------------------------------------------------------------
- ยังไม่ต้องสมัครแพ็กเกจเสียเงินตอนนี้ ลองแพ็กเกจฟรีกับงานวางแผน/ดีบักก่อน
  ถ้าชนลิมิตบ่อยค่อยสมัคร Pro สั้นๆ ช่วงเร่งงาน
- ลิมิตของแพ็กเกจเป็นแบบช่วงเวลา (เซสชัน 5 ชั่วโมง + รายสัปดาห์)
  ไม่ใช่จำนวนโทเคนตายตัว ดูได้ที่ Settings > Usage
- แพ็กเกจสมัครใช้งานไม่รวม API ของแอปคุณเอง (แชตบอทต้องจ่ายแยก)
- Firebase แพ็กเกจฟรีมักพอสำหรับโปรเจกต์นักศึกษา แต่ให้เช็คเงื่อนไข
  ของ Storage ล่าสุด และตั้ง budget alert ไว้
